# テストの規約

## テストは仕様書

- テストファイルを上から読めば、対象の振る舞いが分かる状態を保つ。
- `describe` に対象と状況を、`test` 名に結果を日本語の文で書く(Given/When/Then)。
- テスト名にはコードの言い換えではなく、外から観測できる振る舞いを書く。
- テスト本文は準備 → 実行 → 検証の順に並べ、分岐やループを書かない。

```ts
describe("parseToolVersion", () => {
  describe("`gh version 2.62.0 (2026-01-01)` 形式の出力を受けたとき", () => {
    test("バージョン文字列だけを返す", () => {
      expect(parseToolVersion("gh version 2.62.0 (2026-01-01)")).toBe("2.62.0");
    });
  });
});
```

## 層

1. 純粋関数の単体テスト。
2. 外部効果を環境変数で逸らした統合テスト。
   スクリプトを子プロセスで実行し、`HOME`・`GIT_CONFIG_GLOBAL`・`MISE_BIN` を一時ディレクトリへ、`PATH` を偽コマンドのディレクトリへ向ける。

実機に残すもの: `install.sh`、Homebrew / mise による実インストール、`gh auth login --web` のブラウザ認証、スピナーなど TTY でしか意味を持たない描画。

## 制約

- ランナーは `bun:test`。テストのために `devDependencies` を増やさない。
- 実行者の `~/`(`~/.gitconfig`・`~/.claude` 等)を読み書きしない。外部ネットワークへ出ない。
- 新しい TS は外部効果(ファイルパス・コマンド)を環境変数と `PATH` 経由で参照し、テストから逸らせるように書く。
- Bun は `homedir()` をプロセス起動時に固定するため、`HOME` の差し替えは env の書き換えではなく子プロセスの起動時に行う。
- テストファイルは対象と同じディレクトリに `<対象>.test.ts` として置く。
  テストから実行する入口ファイルは `fixtures/` に置き、`.test.ts` を付けない。
