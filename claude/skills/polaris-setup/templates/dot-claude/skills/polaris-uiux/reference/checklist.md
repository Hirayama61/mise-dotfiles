# UI/UX チェックリスト (4 観点)

出典: CodeZine「AIが作ったUIはなぜ『使いづらい』のか?」(折原レオナルド賢、2026-10-27、<https://codezine.jp/article/detail/29762>)

基準は「主要な利用者が、迷わず、疲れずに目的を達成できるか」。
見た目が整っているかは基準にしない。操作できることと、使えることは別である。
作り手は画面の中身をすべて知っているので、初めて使う人のつまずきに気づきにくい。

観点は上から順に当てる。シグニファイア → フィードバック → UX ライティング → 情報設計。
項目 ID は監査の重複防止キー (`<ID>:<パス>`) に使う。問いを足すときは番号を詰めず、末尾に足す。

## 1. シグニファイア: 操作できることが伝わるか

| ID  | 問い                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------- |
| U01 | 主要な操作が、押すべきものとして一目で分かるか。同じ見た目のボタンが並び、主と従の区別が無くなっていないか |
| U02 | ボタンやリンクは押せるものに見えるか。逆に、押せない文字や印が、押せそうに見えていないか                   |
| U03 | アイコンだけに頼っていないか。押すと何が起きるかを予測できるラベルがあるか                                 |
| U04 | 意味の違う印が、同じアイコンや同じ色を使っていないか                                                       |
| U05 | 意味が `title` 属性 (ホバー) にしか書かれていない印はないか                                                |

## 2. フィードバック: 操作のあとに何が起きているか分かるか

| ID  | 問い                                                                     |
| --- | ------------------------------------------------------------------------ |
| U06 | 操作の直後、処理中、成功、失敗のそれぞれの状態が、利用者に伝わるか       |
| U07 | 反応が無い、止まっている、押せていない、と誤解される余地はないか         |
| U08 | 操作した結果、対象が一覧から消える・移るときに、どこへ行ったかが分かるか |
| U09 | 失敗したとき、入力や作業の途中の内容が残るか                             |

## 3. UX ライティング: 次の行動が分かる言葉か

| ID  | 問い                                                                                       |
| --- | ------------------------------------------------------------------------------------------ |
| U10 | ボタン、エラー、補足文、空の状態の文言が、利用者の次の行動を助けているか                   |
| U11 | システム側の都合や内部の規則の説明で終わっていないか。何をすればよいかが先に書かれているか |
| U12 | エラーは、原因だけでなく、次に何をすればよいかまで書いているか                             |
| U13 | 同じものを、画面によって違う言葉で呼んでいないか                                           |
| U14 | 並んだ絞り込みや選択肢に、何を選ぶものかの見出しがあるか                                   |

## 4. 情報設計: 必要な情報が、必要な順に出ているか

| ID  | 問い                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| U15 | 情報の優先順位が整っているか。主要な情報と補助の情報が、同じ重みで並んでいないか                                                                                                     |
| U16 | 主要な操作への道筋を、ほかの要素がさえぎっていないか                                                                                                                                 |
| U17 | データがあるから、実装したから、という理由だけで出している情報はないか。減らすと判断材料が減り、全部出すと負荷が上がる。どちらを取るかは、主要な利用者がその場面で何をするかで決める |
| U18 | 件数・見出し・バッジなど、同じ画面に出る数どうしが食い違っていないか                                                                                                                 |
| U19 | 今のビューと関係の薄い部品が、広い場所を取っていないか                                                                                                                               |

## 必須問題と応用問題

4 観点を損なうもの、利用者の目的の達成に関わるものは必須問題。
色合い・余白などで、4 観点も目的も損なわない細かな調整は応用問題。後回しにしてよい。
線引きは「デザインか実装か」ではなく、「利用者の目的の達成に関わるか」で行う。

監査ループが扱うのは必須問題だけ。応用問題は起票しない。
