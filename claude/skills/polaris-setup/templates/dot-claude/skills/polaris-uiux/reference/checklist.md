# UI/UX チェックリスト

<https://codezine.jp/article/detail/29762> の内容で差し替える予定。
今は一般的なヒューリスティクス (Nielsen の 10 原則、モバイルの操作性) を元にしている。
Polaris の流儀 (catnose さん流の落ち着いた画面、開いて 3 秒で今日やることが分かる) も入れてある。
CLAUDE.md の「守ること」と食い違うときは CLAUDE.md を優先する。

項目 ID は監査の重複防止キー (`<ID>:<パス>`) に使う。差し替えるときも、残す項目の ID は変えない。

## 見通し

| ID  | 観点                                                                                              | コードで見るところ                                          |
| --- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| U01 | 1 画面 1 目的。開いて 3 秒で、その画面で何をするかが分かる                                        | 画面の最初に描かれる要素、見出し、主ボタンの数              |
| U02 | 状態が見える。保存中・送信中・オフライン・最終同期がいつかが分かる (Nielsen 1)                    | 非同期処理の前後で描画が変わるか、`navigator.onLine` の扱い |
| U03 | 3 状態を描く。空 (データ無し)・読み込み中・エラーのそれぞれに表示がある                           | データを取る hook の戻り値と、それを描く側の分岐            |
| U04 | 利用者の言葉で書く。内部の用語、HTTP のステータス、例外のメッセージをそのまま見せない (Nielsen 2) | エラーの表示箇所、`error.message` の描画                    |

## 操作

| ID  | 観点                                                                                                     | コードで見るところ                                              |
| --- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| U05 | タップ対象は 44px 以上。隣の対象と 8px 以上離れる                                                        | ボタン・チェックボックス・リンクの CSS (`min-height` `padding`) |
| U06 | 戻れる・取り消せる。シートやダイアログに閉じる手段がある。破壊的な操作は確認か取り消しがある (Nielsen 3) | シートの閉じるボタン、背景タップ、Escape、削除や上書きの前      |
| U07 | 二重送信を防ぐ。送信中はボタンを無効にし、再試行で同じ操作が 2 回効かない                                | 送信ハンドラの `disabled`、送信中フラグ、再試行の経路           |
| U08 | 入力を失わない。画面遷移・再読み込み・送信失敗で書きかけが消えない                                       | 下書きの保存、失敗時に入力欄を空にしていないか                  |
| U09 | 誤りを防ぐ。押せない状態は押せない見た目にし、入力の制約は入力前に分かる (Nielsen 5)                     | `disabled` の見た目、`inputmode` `type` `maxLength`             |
| U10 | 覚えさせない。前の画面で見た値を次の画面で思い出させない (Nielsen 6)                                     | シートを開いたときに文脈 (対象の日付やタスク名) が見えるか      |

## 見た目と文言

| ID  | 観点                                                                         | コードで見るところ                                            |
| --- | ---------------------------------------------------------------------------- | ------------------------------------------------------------- |
| U11 | コントラスト。本文は 4.5:1、大きな文字とアイコンは 3:1 以上                  | CSS 変数の色の組み合わせ、薄いグレーの文字                    |
| U12 | 一貫性。同じ操作は同じ言葉・同じ位置・同じ見た目 (Nielsen 4)                 | ボタンの文言 (「保存」「送信」「完了」の揺れ)、主ボタンの位置 |
| U13 | 情報を絞る。今やることに要らない情報を最初の画面に出さない (Nielsen 8)       | 初期表示の要素数、折りたたみの有無                            |
| U14 | 既存の CSS 変数とパターンに揃える。直書きの色・余白が無い                    | `styles.css` の変数と、コンポーネント内の直書き               |
| U15 | 文字が小さすぎない。本文 16px 前後、iOS で入力欄が 16px 未満だとズームされる | `font-size`、入力欄の文字サイズ                               |

## 失敗と助け

| ID  | 観点                                                                                             | コードで見るところ                       |
| --- | ------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| U16 | エラーから立て直せる。何が起きたか、次に何をすればよいかを書く。再試行の手段がある (Nielsen 9)   | エラー表示と再試行ボタン                 |
| U17 | 待たせる処理に反応がある。タップから 100ms 以内に何かが変わる                                    | 楽観的更新、ボタンの押下状態             |
| U18 | 画面の外の変化に強い。スマホの回転、キーボードの表示、セーフエリア (ノッチ) で操作対象が隠れない | `env(safe-area-inset-*)`、固定配置の要素 |
