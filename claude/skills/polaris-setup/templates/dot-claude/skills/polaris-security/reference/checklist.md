# セキュリティ チェックリスト (SPA / PWA)

ブラウザだけで動き、外部 API をトークンで呼ぶ SPA / PWA を想定している。
CLAUDE.md の「守ること」(通信先や秘密の扱い) と食い違うときは CLAUDE.md を優先する。

項目 ID は監査の重複防止キー (`<ID>:<パス>`) に使う。項目を足すときは番号を詰めない。

## 秘密の扱い

| ID  | 観点                                                                                                                                     | コードで見るところ                                                      |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| S01 | トークンの保存場所。どこに置き (localStorage、IndexedDB、メモリ)、いつ消すかが決まっている。XSS が起きたときに読まれる範囲を把握している | トークンを読み書きする箇所、ログアウトや設定のリセット                  |
| S02 | トークンが決まった通信先以外に出ない。`Authorization` ヘッダを付ける fetch の宛先が固定されている                                        | fetch のラッパー、URL を組み立てる箇所、リダイレクトの追従              |
| S03 | 秘密が URL・ログ・エラー表示・Issue 本文・analytics に混ざらない                                                                         | `console.*`、エラーメッセージの組み立て、クエリ文字列、利用者が送る本文 |
| S04 | 秘密が commit されていない。ビルド成果物や `.env` 系、テストのフィクスチャに実物が無い                                                   | `git grep` で `ghp_` `github_pat_` `sk-` などの形、`.gitignore`         |
| S05 | ビルド時の環境変数が公開物に埋まる前提で扱われている (`VITE_*` などはすべて公開される)                                                   | `import.meta.env` の参照                                                |

## 入力と描画

| ID  | 観点                                                                                                            | コードで見るところ                                    |
| --- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| S06 | `dangerouslySetInnerHTML` `innerHTML` `insertAdjacentHTML` に外から来た文字列が入らない。入るなら無害化している | 該当 API の Grep                                      |
| S07 | Markdown や HTML を描くとき、`javascript:` などのスキームのリンクや `on*` 属性が通らない                        | Markdown の変換、`href` の組み立て                    |
| S08 | 外から来た値で URL のパスやクエリを組み立てるとき、エンコードしている (`../` や `?` で宛先が変わらない)         | `encodeURIComponent` の有無、テンプレート文字列の URL |
| S09 | `eval` `new Function` `setTimeout(文字列)` を使っていない                                                       | 該当 API の Grep                                      |

## 配信と通信

| ID  | 観点                                                                                                       | コードで見るところ                                                          |
| --- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| S10 | 通信先が限られている。CSP (`connect-src` など) を置けるなら置いている                                      | `index.html` の meta、ホスティングのヘッダ                                  |
| S11 | サードパーティのスクリプト・フォント・画像を読み込んでいない。読むなら SRI (`integrity`) がある            | `index.html`、`<script src>`、CSS の `@import` と `url()`                   |
| S12 | Service Worker が認証付きの API の応答や秘密をキャッシュしない。キャッシュ対象が静的ファイルに限られている | PWA の設定 (`workbox` の `runtimeCaching`、`navigateFallback`)、手書きの SW |
| S13 | 古い Service Worker やキャッシュが、修正後も古いコードを配り続けない (更新の経路がある)                    | `registerType`、`skipWaiting`、更新の通知                                   |

## 依存と CI

| ID  | 観点                                                                                                                                               | コードで見るところ                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| S14 | 依存に既知の脆弱性が無い (`bun audit`、`pnpm audit` など)。実行時に使う依存を優先して見る                                                          | 監査コマンドの出力、`dependencies` と `devDependencies` の区別 |
| S15 | lockfile が commit され、CI が `--frozen-lockfile` 相当で入れている                                                                                | lockfile、CI の install ステップ                               |
| S16 | GitHub Actions の `permissions` が最小。ワークフロー全体に `write` を広く付けていない                                                              | `.github/workflows/*.yml` の `permissions`                     |
| S17 | 外部の Action をタグではなくコミット sha で固定している (少なくとも書き込み権限を持つジョブで)                                                     | `uses:` の行                                                   |
| S18 | `pull_request_target` や `workflow_run` で、PR 側のコードを書き込み権限付きで checkout・実行していない                                             | トリガーと `actions/checkout` の `ref`                         |
| S19 | ワークフローの `run:` に、PR のタイトルや本文、ブランチ名 (`github.event.pull_request.title` など) を式で直接埋めていない。`env:` 経由で渡している | `run:` の中の `github.event`                                   |
